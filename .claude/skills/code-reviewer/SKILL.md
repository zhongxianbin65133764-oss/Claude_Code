# 代码审查 Skill

## 目的
提供全面的代码审查，识别潜在问题、安全隐患、性能瓶颈和改进机会。

## 审查流程

### 1. 获取代码变更
首先获取需要审查的代码：
- 使用 `git diff` 查看未提交的变更
- 或使用 `git diff HEAD~1` 查看最近的提交
- 或审查用户指定的文件

### 2. 代码质量检查
检查以下方面：
- **命名规范**：变量、函数、类名是否清晰且符合规范
- **函数复杂度**：函数是否过长或过于复杂
- **代码重复**：是否存在重复代码（DRY 原则）
- **注释质量**：复杂逻辑是否有适当的注释
- **代码风格**：是否符合项目风格指南

### 3. 安全性检查
识别常见的安全问题：
- **敏感信息泄露**：检查硬编码的密钥、密码、API token
- **输入验证**：用户输入是否经过验证和清理
- **SQL 注入**：数据库查询是否使用参数化查询
- **XSS 漏洞**：输出是否经过适当的转义
- **认证授权**：权限检查是否正确实现
- **依赖安全**：是否使用了有已知漏洞的依赖

### 4. 性能评估
识别性能问题：
- **算法复杂度**：是否使用了高效的算法
- **不必要的循环**：是否有 O(n²) 可以优化为 O(n)
- **数据库查询**：是否存在 N+1 查询问题
- **内存泄漏**：资源是否正确释放
- **缓存机会**：是否有重复计算可以缓存

### 5. 测试覆盖
评估测试情况：
- 关键功能是否有测试
- 边界条件是否被测试
- 错误处理是否有测试
- 建议额外的测试场景

### 6. 架构和设计
评估设计质量：
- **单一职责**：每个函数/类是否只做一件事
- **依赖关系**：模块间的耦合度是否合理
- **可扩展性**：代码是否易于扩展
- **错误处理**：错误是否得到妥善处理

## 输出格式

审查结果应包含：

### 总体评估
- 代码质量等级：优秀/良好/需要改进/存在问题
- 主要发现摘要（3-5 点）

### 详细问题列表
对每个问题提供：
1. **问题位置**：文件名和行号
2. **问题类型**：质量/安全/性能/测试
3. **严重程度**：🔴 严重 / 🟡 中等 / 🔵 建议
4. **问题描述**：清晰说明问题
5. **改进建议**：具体的修改建议（包含代码示例）

### 积极反馈
指出代码中做得好的地方：
- 良好的设计决策
- 清晰的代码结构
- 优秀的命名
- 完善的错误处理

### 改进优先级
按优先级排序建议：
1. **必须修复**：安全问题、严重 bug
2. **应该修复**：性能问题、代码质量问题
3. **可以改进**：风格建议、优化机会

## 示例

### 输入
用户说："帮我审查一下最近的代码变更"

### 输出
```
## 代码审查报告

### 总体评估
代码质量：良好 ✓
主要发现：
- 发现 1 个安全隐患（密钥硬编码）
- 发现 2 个性能优化机会
- 代码结构清晰，测试覆盖良好

### 详细问题

#### 🔴 严重：API 密钥硬编码
**位置**：`src/api/client.py:15`
**问题**：API 密钥直接写在代码中，存在泄露风险
```python
# 当前代码
api_key = "sk-1234567890abcdef"
```
**建议**：使用环境变量
```python
# 改进后
import os
api_key = os.environ.get("API_KEY")
if not api_key:
    raise ValueError("API_KEY environment variable is required")
```

#### 🟡 中等：数据库查询效率低
**位置**：`src/models/user.py:42`
**问题**：在循环中执行数据库查询（N+1 问题）
**建议**：使用批量查询或 JOIN

#### 🔵 建议：函数过长
**位置**：`src/services/processor.py:78-156`
**问题**：`process_data` 函数有 78 行，建议拆分
**建议**：提取为多个小函数，每个函数负责一个步骤

### 做得好的地方 ✨
- 错误处理完善，所有异常都被妥善捕获
- 函数命名清晰，见名知意
- 添加了单元测试，覆盖了主要场景

### 改进优先级
1. **立即修复**：移除硬编码的 API 密钥
2. **尽快优化**：解决 N+1 查询问题
3. **后续改进**：重构长函数
```

## 注意事项
- 保持建设性和友好的语气
- 提供具体可行的建议，而不是泛泛而谈
- 平衡批评和鼓励
- 如果代码整体质量很好，要明确指出
- 尊重不同的编码风格，除非违反最佳实践
